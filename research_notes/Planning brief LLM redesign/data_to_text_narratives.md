# Trustworthy LLM data-to-text narratives: products, research, style, verification, cost

Research notes compiled 2026-10-29 for the LDT planning brief redesign.
Scope: how products and research generate natural-language narratives from structured numbers with LLMs, what they compute deterministically, how they verify and label output, how policy-audience style guides say numbers and uncertainty should be written, and what per-entity generation costs at LDT scale (about 1,100 municipalities per yearly release).
Material older than 2024 is labelled as such.
Context reminder: LDT stack is Next.js, Supabase and the OpenAI API; notes flag provider-specific features and provider-neutral alternatives.

## How do current products generate narratives from data, and what is deterministic versus left to the model?

### Takeaway
Every mature BI product that ships generated narratives follows an "insights first, then words" pattern: a deterministic layer computes facts (period change, drivers, outliers, trends), ranks them by impact, and the LLM only verbalises the selected facts, often with a visible pointer back to the source visual or cell.
No product lets the model do arithmetic on raw rows and present the result as a narrative; the ones with deterministic-only engines (Arria, classic Power BI Smart Narrative) still exist and are positioned as the accuracy baseline that LLMs are layered on top of.

### Cited Findings
- Tableau Pulse's Insights Platform uses "standardized, deterministic statistical models" that detect facts about a metric that are "guaranteed to be accurate"; these facts "serve as the ground truth" and, when AI in Tableau is on, "the most relevant facts are processed by AI to produce natural-language insight summaries" — [Tableau Help: The Insights Platform and Insight Types in Tableau Pulse](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm)
- Tableau Pulse's deterministic insight types are: Period Over Period Change (always on), Correlated Metrics, Record-level Outliers, Forecast (with a confidence range, shown "only when the platform is confident in it"), Current Trend ("rate, direction, and fluctuation"), Trend Change Alert, Unexpected Values (outside "the expected range based on past observations"), Goal and Threshold Breakdown, Pace to Goal, Top Drivers, Top Detractors, Concentrated Contribution Alert (few members account for 50% or more), Top Contributors, Bottom Contributors — [Tableau Help](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm)
- Tableau Pulse ranks: "Insights are ranked based on impact to the metric," and only Period Over Period Change and Unexpected Values feed into the LLM-written insight summary; analysts can switch individual insight types on or off — [Tableau Help](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm)
- Tableau Pulse's architecture is three layers: a metrics layer (measure, aggregation, time grain, definitional filters, related dimensions, metadata such as whether "up is good"), an insights platform (insight generation, ranking, summaries, templated follow-up questions), and delivery; "Just the most important insights are communicated to the user" — [InterWorks, Feb 2024](https://interworks.com/blog/2024/02/28/take-your-pulse-how-does-tableau-pulse-work/)
- Power BI's classic Smart Narrative (now "Custom mode" of the Narrative visual) is rule-based: it "automatically analyzes trends," "calculates growth," generates "up to four summaries per visual and up to 16 per page," uses "dynamic values" bound to fields and measures that update with cross-filtering, and shows a hidden-summary symbol when "current data and filters produce no result for the value" — [Microsoft Learn: Create Smart Narrative Summaries (page dated 2026-09-25)](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-smart-narrative)
- Power BI's Copilot mode of the Narrative visual "pulls information from what is on the report canvas, not the underlying semantic model"; "The summary only takes into account the data that's visualized by the selected visuals"; the generated body "can't [be] edit[ed]" directly, only steered by prompts; and footnotes link each claim to a specific visual ("Power BI highlights the visual that the footnote refers to") — [Microsoft Learn: Create a narrative visual with Copilot (page dated 2026-05-11)](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-create-narrative)
- Power BI stores the prompt with report metadata "so it can generate the summary each time a report loads," and the narrative "doesn't automatically update" on filter change; users press a refresh button — [Microsoft Learn](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-create-narrative)
- Looker Conversational Analytics: "Gemini determines fields, filters, sorts, and limits, but Looker composes and runs the query from the LookML model," so the agent "doesn't write the full SQL"; text summaries come from "built-in Gemini capabilities to interpret and summarize results"; it "doesn't yet support forecasting, correlation, or anomaly detection" — [Google Cloud: Conversational Analytics overview](https://docs.cloud.google.com/looker/docs/conversational-analytics-overview)
- Looker accuracy aids are "verified queries (golden queries)" and "agent instructions"; a Google deck recommends defining calculations as LookML measures for "a single source of truth" and hiding ID fields "to reduce noise" — [Google Cloud overview](https://docs.cloud.google.com/looker/docs/conversational-analytics-overview); [Google deck: Conversational analytics in Looker](https://services.google.com/fh/files/misc/conversational_analytics_in_looker.pdf)
- ThoughtSpot Spotter uses LLMs "to generate search tokens, not direct text-to-SQL syntax," which map to its semantic layer; ThoughtSpot says "the SQL query ThoughtSpot generates is the only thing that ever runs against your cloud data warehouse" and that Spotter's "deterministic reasoning keeps the full chain of logic and data traceable" (vendor claims) — [ThoughtSpot SpotMap slides, Feb 2026](https://media.thoughtspot.com/pdf/ThoughtSpot-SpotMap-Slides-February-2026.pdf); [ThoughtSpot trust page](https://www.thoughtspot.com/trust/enterprise-grade-ai)
- Amazon Quick (formerly QuickSight) data stories: "Data story drafts are not meant to replace your own ideas or to perform analysis. Rather, data stories are a starting point to customize and expand on"; the draft "combine[s] your prompt with selected visuals" — [AWS docs: Working with data stories](https://docs.aws.amazon.com/quick/latest/userguide/working-with-stories.html)
- AWS states that "QuickSight does not use customer data to train the LLMs" and that existing data governance "will remain in place" for generative BI — [AWS BI blog: Amazon Q in QuickSight GA](https://aws.amazon.com/blogs/business-intelligence/amazon-q-is-now-generally-available-in-amazon-quicksight-bringing-generative-bi-capabilities-to-the-entire-organization)
- Arria positions its platform as "best-of-breed deterministic natural language generation together with" LLM generation; the 2025 white paper frames deterministic and probabilistic generation as suited to different needs and used together — [Arria WP102 Converging Technologies 2025 (PDF)](https://www.arria.com/wp-content/uploads/2026/03/WP102-Converging-Technologies-2025.pdf); Dec 2024 platform announcement "Combining Deterministic Accuracy with LLM Innovation" — [Arria blog](https://www.arria.com/blog/?p=2027)
- Narrative Science Quill (now inside Tableau via Salesforce) is ontology- and rule-driven: its patents describe NLG "using composable communication goals and ontologies," and note that template-only NLG systems "typically suffer from a variety of shortcomings" (pre-2024 material) — [USPTO patent 12086562](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/12086562); [Intellyx, 2018](https://intellyx.com/2018/03/08/narrative-science-ai-driven-analytics-and-natural-language-generation-for-insightful-dynamic-narratives/)
- Datawrapper deliberately ships no LLM chart suggestions or automatic insight generation, per a 2026 German review (secondary source) — [ki-syndikat.de review](https://www.ki-syndikat.de/tools/datawrapper/); third parties expose Datawrapper to agents through an MCP server — [datawrapper-mcp listing](https://skillselion.com/mcp/tool/io.github.palewire/datawrapper-mcp)
- Observable Canvases integrate AI for "finding tables, generating charts, and summarizing takeaways" (secondary listing) — [G2 Observable reviews](https://g2.com/products/observable/reviews); Hex's April 2026 changelog covers the agent building charts, not narratives — [Hex changelog 2026-04-30](https://learn.hex.tech/changelog/2026-04-30)
- Research mirror of the product pattern: the NAACL 2025 insight-generation pipeline is "Hypothesis Generator" (questions) -> "Query Agent" (SQL against a database) -> "Summarization module" (verbalise); baselines included Microsoft Quick Insights and ChatGPT data analysis — [arXiv 2503.11664](https://arxiv.org/abs/2503.11664)

### Inferences
- The LDT brief's first stage ("score evidence" from component scores and trends) maps directly to Tableau Pulse's Period Over Period Change + Current Trend + Top Drivers/Detractors + Unexpected Values; those four are computable in SQL or TypeScript from LDT's yearly series, national and province averages and ranks, and can be ranked by absolute contribution to the pillar change before the LLM sees anything.
- Products converge on a strict contract: the LLM receives a small, typed "fact sheet" (facts already selected and ranked) and returns prose; the LLM never receives raw rows and never computes deltas. The ones that do hand raw visuals to the model (Power BI Copilot, Amazon Quick) treat the output as a draft the author must check.
- Power BI's footnote-to-visual linkage and Tableau's "fact is ground truth" are two implementations of the same idea LDT can adopt: every sentence carries an ID of the fact it verbalises.
- Datawrapper's refusal to add AI narratives is a useful data point for a public-sector tool: a journalism-grade chart tool chose zero generated prose over risk, so an LDT narrative needs a visible verification path to justify its existence.

### Gaps
- Tableau's full Pulse Security Overview (which lists LLM partners and prompt contents) is behind a login; only the summary page was readable — [Salesforce compliance page](https://compliance.salesforce.com/en/documents/a006e0000161nRfAAI)
- No ThoughtSpot primary document explains where the LLM's role ends inside Spotter; the "deterministic" claims are marketing.
- No public engineering blog describes how Power BI Copilot serialises visuals into the prompt or how it checks numbers after generation.
- I found no 2025 to 2026 entrant with a documented architecture beyond the vendors above; Hex and Observable changelogs mention charts and takeaways but not numeric verification.

## What does 2023 to 2026 research say about wrong numbers in LLM data-to-text, and which mitigations work?

### Takeaway
Numeric hallucination is the dominant table-to-text error class even for large models, and the mitigations with measured gains are all post-hoc, claim-level checks against the source cells (cell-anchored NLI, executable Python verification, renderer-side claim-bound numbers) rather than better prompting; model scale and fine-tuning alone do not remove the problem and in one study made it worse.

### Cited Findings
- ToTTo (2021, older material): "the top performing baseline appears to hallucinate information ~20% of the time," and models "struggle with hallucination, numerical reasoning, and rare topics" — [Google Research blog](https://research.google/blog/totto-a-controlled-table-to-text-generation-dataset/)
- TabFaith (SURGeLLM workshop, ACL, July 2026): a benchmark of "2,400 (table, summary, error annotation) triples" from ToTTo plus an enterprise set (financial reports, clinical notes, operational dashboards); error types include "hallucinating numerical values," misattributing entities to rows or columns, "fabricating comparative rankings," and conflating temporal references — [ACL Anthology 2026.surgellm-1.21](https://aclanthology.org/2026.surgellm-1.21/)
- TabFaith shows standard metrics miss these errors: BLEU r = 0.24 and PARENT r = 0.60 with human faithfulness judgments, versus r = 0.94 for its reference-free STAF metric, which checks "summary claims against individual table cells using natural language inference" — [ACL Anthology](https://aclanthology.org/2026.surgellm-1.21/)
- TabFaith's CAVE ("Cell-Anchored Verification and Editing") is a "training-free post-processing method" that flags unfaithful claims, links them to cells and regenerates the spans; it improves STAF by +0.14 on average across five LLMs, with the largest gain on numerical errors (+0.17) — [ACL Anthology](https://aclanthology.org/2026.surgellm-1.21/)
- STAT-TO-TEXT (arXiv, Sept 2026) verifies each quantified inference ("all, some, no, most") by running an LLM-generated Python checker against the table; the checker "closely aligns with human judgments"; among four open-weight models, GPT-OSS-120B produced "the most faithful inferences," and the authors conclude model scale and family matter — [arXiv 2609.23966](https://arxiv.org/abs/2609.23966)
- ChaTS-Pi (ACL 2024): a reference-free critic reconstructs the table from the chart and scores the summary "one sentence at a time" with a tabular entailment model; at inference it repairs and ranks candidates by "removing not supported sentences," matching human ratings better than reference-based metrics — [arXiv 2405.19094](https://arxiv.org/abs/2405.19094)
- Proof-Carrying Numbers (arXiv, Sept 2025, World Bank author Aivin Solatorio): RAG, citations and uncertainty estimates "cannot guarantee fidelity"; PCN emits numeric spans as "claim-bound tokens," a renderer-side verifier checks each under a policy (exact equality, rounding, aliases, tolerance), "only claim-checked numbers are marked as verified," giving "fail-closed behavior"; the paper is formal (soundness, completeness, monotonicity proofs) and reports no benchmark numbers — [arXiv 2509.06902](https://arxiv.org/abs/2509.06902)
- NAACL 2025 insight-generation pipeline: the summariser measures hallucination by "splitting the insight into different claims" and having an LLM score contradictions against the query answers (G-Eval style), then refines with Reflexion until the score passes a threshold (τh = 0.9); a manual review of 58 summaries "found no LLM hallucinations in summarizing or transcribing SQL results," with most errors coming from semantic parsing (the SQL step); the deterministic Quick Insights baseline "has perfect correctness by design" — [arXiv 2503.11664 full text](https://arxiv.org/html/2503.11664v1)
- Scaling does not fix data-to-text faithfulness: a 2025 TMLR paper reports factual inconsistency in data-to-text "grows with model size, compute and fine-tuning data"; a companion study found larger models generally help but smaller T5 and BART models can match them on some datasets — [ISI Kolkata repository, TMLR 2025](https://digitalcommons.isical.ac.in/journal-articles/5364); [companion study](https://digitalcommons.isical.ac.in/journal-articles/5199)
- Program-of-Thought (TMLR 2023, older material): the LLM writes Python and an interpreter runs it, "separating computation from reasoning"; a secondary summary reports about 12% average gain over chain-of-thought including on the table-based TabMWP set — [Program-of-Thoughts repo](https://github.com/wenhuchen/Program-of-Thoughts); [arXiv 2211.12588](https://arxiv.org/pdf/2211.12588v1)
- PoT's benefit depends on executable code: FinanceMath found models with an execution rate below 60% degrade under PoT, while above 80% accuracy reflects reasoning ability — [arXiv 2311.09797](https://arxiv.org/pdf/2311.09797)
- Table QA benchmarks treat code execution as a standard baseline: TableBench uses PoT alongside textual and symbolic chain-of-thought — [arXiv 2408.09174](https://arxiv.org/pdf/2408.09174); PoTable (interpreter + LLM planner) reports "over 4% higher absolute accuracy" than runner-ups — [arXiv 2412.04272](https://arxiv.org/abs/2412.04272v1)
- Self-consistency for numeric claims: an EMNLP 2025 Findings paper (Chungkham, Venktesh, Setty, Anand) samples multiple reasoning paths to fact-check numerical claims and reports reduced "reasoning drift" — [ACL Anthology author page](https://aclanthology.org/people/vinay-setty)
- Small fact-checkers for numbers: CLEF 2025 CheckThat! Task 3 (numerical claim verification) entries used a LoRA-tuned Mistral-Small-24B and a lightweight LLM judge pipeline — [CEUR paper 78](https://ceur-ws.org/Vol-4038/paper_78.pdf); [CEUR paper 55](https://ceur-ws.org/Vol-4038/paper_55.pdf)
- Claim-level numeric grounding in agents: VeriGraph decomposes answers into atomic claims and extracts numeric expressions for "numeric-overlap retrieval" to compute a Grounding Rate — [arXiv 2606.16603](https://arxiv.org/pdf/2606.16603); VeriGate is a four-gate checker for evidence IDs, entities, numbers and claim types — [ACL Anthology 2026.groundlm-1.5](https://aclanthology.org/2026.groundlm-1.5/); VeriFin grounds each financial line item to a unique XBRL fact and checks formulas with Z3 — [Hugging Face papers 2608.10213](https://huggingface.co/papers/2608.10213)
- LLM-as-judge for factual consistency dates to 2023 (older): ChatGPT zero-shot judged summary consistency — [arXiv 2303.15621](https://ar5iv.labs.arxiv.org/html/2303.15621); the 2026 SUMMIR framework checked 281,163 LLM-generated sports insights with sentence-level NLI (SummaC) before ranking — [arXiv 2604.04947](https://arxiv.org/pdf/2604.04947)
- Provider structured outputs guarantee shape, not truth: OpenAI says responses "adhere to your supplied JSON Schema" in strict mode, refusals are "programmatically detectable," and structured outputs are supported in the Batch API; the page warns of edge cases (refusal, `max_output_tokens` truncation) and never claims content correctness — [OpenAI Structured outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs)
- Anthropic Citations attach `cited_text` pointers that are "guaranteed to contain valid pointers to the provided documents," support "custom content documents" where "no further chunking is done" (so each fact can be one citable block), do not count `cited_text` toward output tokens, but "Citations cannot be used together with structured outputs" (400 error) — [Anthropic Citations docs](https://platform.claude.com/docs/en/build-with-claude/citations)

### Inferences
- For LDT, the cheapest mitigation with measured effect is a deterministic post-check: extract every number and comparison phrase from the generated text and match it to the fact sheet (PCN-style exact or rounded match). This is provider-neutral and needs no second model.
- A second-pass LLM "contradiction check per claim" (NAACL 2025, TabFaith CAVE) is the next layer; both report it catches what prompting misses, and a small or cheap model suffices because the task is entailment against a short fact list, not open reasoning.
- Program-of-thought is the wrong tool for LDT's stage one: LDT already has the numbers; the arithmetic should be done in SQL or TypeScript before the prompt, which is what every product does. PoT only matters if later brief stages ask the model to derive new quantities.
- OpenAI structured outputs can enforce a schema in which each sentence carries `fact_ids: string[]`; that gives claim-level citation without Anthropic's Citations feature and works in the Batch API. The provider-neutral version is the same schema validated with Zod or JSON Schema server-side.
- The NAACL finding that the SQL step, not the verbalisation step, produced the errors supports keeping LDT's fact computation in reviewed code rather than letting the model query Supabase.

### Gaps
- No paper reports a per-model numeric error rate on dashboard-style summaries for current frontier closed models (GPT-5.x, Claude 4.x or later); TabFaith does not name its five LLMs in the abstract, and STAT-TO-TEXT tested only open-weight models.
- I could not read the full TabFaith paper or the TMLR scaling paper, so the exact models, sizes and effect sizes are unverified beyond the abstracts.
- No source directly compares "structured fact sheet" prompting against "raw table" prompting on numeric error rate; the evidence for fact sheets is architectural (products do it) and indirect (NAACL: no hallucinations when summarising SQL results).

## How should a generated narrative express comparisons, trend magnitude, uncertainty and missing data without overclaiming causality?

### Takeaway
UK government statistical guidance (GSS, ONS, OSR) is the most concrete source: describe change by direction, absolute size and relative size, compare to at least two reference points, call non-significant movement "broadly stable" or "indicative," separate "what we can conclude" from "what we cannot," and avoid stand-alone caution phrases that readers learn to ignore.

### Cited Findings
- "Describe the direction of change, its absolute size and its relative size over time"; put numbers in context with "the previous period, the same period last year, and a longer series"; give the uncertainty "in the estimate of change, not only in the levels" — [GSS: Communicating quality, uncertainty and change](https://analysisfunction.civilservice.gov.uk/policy-store/communicating-quality-uncertainty-and-change/)
- For non-significant change: "focus on the longer term," describe changes within random variation as "indicative, rather than definitive," use "broadly stable," and explain "the usual level of change between points in the series"; model sentence: the change "is not statistically significant and it is likely that the natural variation in the figures explains the change" — [GSS](https://analysisfunction.civilservice.gov.uk/policy-store/communicating-quality-uncertainty-and-change/)
- Word choices: use "estimates" throughout; avoid "care must be taken" and "exercise caution" unless "supported by practical advice"; be careful with "error," "bias" and "uncertainty" for lay audiences — [GSS](https://analysisfunction.civilservice.gov.uk/policy-store/communicating-quality-uncertainty-and-change/)
- Structure conclusions as "What we can conclude" and "What we cannot conclude"; "pre-empt any misunderstanding and overinterpretation"; stay "neutral and impartial, letting the facts speak for themselves"; explain that several factors may combine rather than attributing change to one cause (illustrated, not stated as a rule) — [GSS](https://analysisfunction.civilservice.gov.uk/policy-store/communicating-quality-uncertainty-and-change/)
- Small areas carry more error ("a higher degree of error associated with it"); warn users "not to infer trends" when the source does not support a time series; put "vital quality messages up front, in the key findings, rather than in footnotes" — [GSS](https://analysisfunction.civilservice.gov.uk/policy-store/communicating-quality-uncertainty-and-change/)
- OSR found "around," "nearly" and "about" usefully signal inexact figures, while "figures should be treated with caution" becomes "so overused that readers ignore them"; confidence intervals published without explanation led users to read the estimate as "the 'true' value"; "no evidence of a difference" was confused with "evidence of no difference"; the Welsh Index of Multiple Deprivation infographic is best practice because it lists what ranks can and cannot be used for, including "using ranks to infer absolute change over time" — [OSR: Approaches to presenting uncertainty, findings](https://osr.statisticsauthority.gov.uk/publication/approaches-to-presenting-uncertainty-in-the-statistical-system/pages/3)
- Writing about data: inverted pyramid ("the most important information should be first"), one idea per paragraph, sentences around 25 words, pair precise and plain figures ("about one-third (32%)"), give context for whether "a 2% rise [is] unusual compared with previous years, other countries, or a policy target," and state "what the data can and cannot support" up front — [Analysis Function: Writing about data](https://analysisfunction.civilservice.gov.uk/policy-store/writing-about-data/)
- ONS number style: numerals for 10 and above, words for zero to nine except when "relate[d] directly to the statistics"; "Always use the same number of decimal places when listing a sequence of numbers or percentages"; leading zero (0.6%); ranges with "to" not a hyphen; rankings "first" to "ninth" as words then "10th"; write "positive" or "negative" in text, not +/- — [ONS service manual: Writing numbers](https://service-manual.ons.gov.uk/content/numbers/writing-numbers)
- ONS on percentage points: always write "percentage" (never "%age") and "points" plural except for "1 percentage point" — [ONS service manual: Percentages](https://service-manual.ons.gov.uk/content/numbers/percentages)
- A move from 4% to 6% is "2 percentage points" but "the percentage change is 50%" (illustrative secondary source) — [Canadian Mortgage Trends](https://www.canadianmortgagetrends.com/2011/11/percentage-points-pp/); the US GPO Style Manual lists "5 percentage points" beside "a 5-percent increase" as distinct forms (older material) — [GPO Style Manual](https://www.govinfo.gov/content/pkg/GPO-STYLEMANUAL-2000/html/GPO-STYLEMANUAL-2000-16.htm)
- NHS content guide: numerals for "statistics, times, measurements and lists" because readers scan for them; "use statistics sparingly" — [NHS service manual](https://service-manual.nhs.uk/content/numbers-measurements-dates-time)
- Tableau Pulse shows a forecast "only when the platform is confident in it," and its Unexpected Values insight is defined relative to "the expected range based on past observations," i.e. magnitude is expressed against a baseline, not as a bare number — [Tableau Help](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm)
- Power BI Smart Narrative hides a value when "current data and filters produce no result," and a summary "is empty when no insights are available" (for example a flat line) rather than inventing text — [Microsoft Learn](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-smart-narrative)

### Inferences
- A concrete LDT sentence pattern that satisfies GSS: "[Pillar] scored 58 in 2025, 4 points above the national average (54) and 2 below the province average (60). It rose 6 points since 2021, the largest rise among the three pillars." Direction, absolute size, two reference points, and relative size are all present and all computable.
- Score changes under a threshold (set from the observed year-to-year noise in the series, per GSS "usual level of change") should be verbalised as "broadly stable," never as "fell slightly."
- LDT ranks need the WIMD-style guardrail text: ranks compare municipalities within a year and cannot be used to infer absolute change across years, since the denominator (other municipalities) moves.
- Causality: the fact sheet should contain no causal fields, and the prompt should forbid "because," "due to," "driven by" unless the fact sheet carries a "driver" fact computed as contribution to change (Tableau's Top Drivers definition, which is compositional, not causal).
- Missing indicators: follow Power BI Smart Narrative and omit the sentence rather than let the model write around a gap; the fact sheet should carry an explicit `missing` list so the narrative can state "two of five indicators were not reported in 2025" when coverage matters.

### Gaps
- I did not find World Bank or IMF prose-style guidance on describing change or uncertainty; the World Bank 2020 style guide PDF returned 404 and is described elsewhere only as a supplement to the Chicago Manual of Style — [RePEc record](https://ideas.repec.org/b/wbk/wbpubs/33367.html); IMF material found was only its "Assumptions and Conventions" note (basis points = hundredths of a percentage point) — [IMF Fiscal Monitor conventions](https://www.imf.org/-/media/files/publications/fiscal-monitor/2017/october/pdf/fmassumconv.pdf.md)
- GSS guidance does not address percentage versus percentage-point change explicitly; that comes from ONS style and generic style manuals.
- No source gives a numeric threshold for when a composite-index change is "meaningful"; LDT would need to derive one from its own series variance or from the index methodology.

## What do style guides and practitioners say about tone and structure for policy audiences?

### Takeaway
Government content and statistics guidance agree: lead with the main message, one idea per paragraph, short sentences, plain words with technical terms explained, numerals for statistics, consistent decimals, and the limitations stated where readers will see them; the brief's audience (municipal and national officials) is non-technical by default.

### Cited Findings
- "Assume the audience has no technical knowledge"; "explain technical terms and write out abbreviations on first use"; keep sentences "around 25 words"; use short descriptive headings instead of "abstract" or "executive summary"; readers scan in an F-shape so the key point goes top-left — [Analysis Function: Writing about data](https://analysisfunction.civilservice.gov.uk/policy-store/writing-about-data/)
- "Explain the overall trend, then highlight specific areas of interest"; "compare groups to show meaningful differences"; "state the implications of the data"; integrate charts and tables with the text and explain them — [Analysis Function](https://analysisfunction.civilservice.gov.uk/policy-store/writing-about-data/)
- Ethnicity Facts and Figures (GOV.UK) writing principles: content must meet user needs, be "clear and concise," and stay understandable "even when the statistical ideas are complex" — [Ethnicity facts and figures style guide](https://ethnicity-facts-figures.service.gov.uk/style-guide/principles)
- ONS: numerals for all numbers 10 and over, consistent decimal places in a sequence, never start a sentence with a numeral, "to" for ranges — [ONS service manual](https://service-manual.ons.gov.uk/content/numbers/writing-numbers)
- GOV.UK content design guidance has an update history that includes renaming "national statistics" to "accredited official statistics" (Aug 2024), which matters for how a tool should label official sources — [GOV.UK content design change log](https://govukdiff.njk.onl/update/2024-08-01T09:19:00+01:00/www.gov.uk/guidance/content-design)
- Tableau Pulse describes its summaries as "business-friendly language" of "the most important and impactful metrics" — [InterWorks](https://interworks.com/blog/2024/02/28/take-your-pulse-how-does-tableau-pulse-work/)
- Power BI lets authors "curate the tone and specificity of the narrative with suggested and custom prompts," and the prompt limit in Copilot mode is 10,000 characters — [Microsoft Learn narrative](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-create-narrative); [Microsoft Learn smart narrative](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-smart-narrative)

### Inferences
- For LDT, a fixed paragraph template (headline position vs national, change since 2021, strongest and weakest component, data coverage) enforces the inverted pyramid and keeps tone constant across 1,100 units, which an open-ended prompt will not.
- The three countries have different official languages; ONS-style numeral rules are English-specific, so the style spec should live in the fact-to-text layer per locale rather than in the prompt.

### Gaps
- No World Bank, IMF or GPB house style for narrative prose was located; the World Bank style guide is a Chicago supplement focused on editorial mechanics, not analytical tone.
- No practitioner write-up specific to municipal-performance indices (for example, OECD or UN-Habitat city index narratives) was found in this pass.

## How do products label AI-generated content, let users verify it, and collect feedback?

### Takeaway
Labelling is a general disclaimer ("can generate output that seems plausible but is factually incorrect"), verification is a link from each claim back to the source visual or query, and feedback is thumbs up/down with a reason code; Tableau is the only product where feedback changes ranking, and all of them keep the generated body non-editable or clearly separated from author text.

### Cited Findings
- Power BI: the docs instruct users to "Read through the summary to make sure it's accurate"; footnotes reference specific visuals and "Power BI highlights the visual that the footnote refers to"; the Copilot body cannot be edited directly but can be copied into the editable Smart Narrative body — [Microsoft Learn](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-create-narrative)
- Microsoft's HAX Toolkit example shows Copilot in Outlook placing "AI generated content may be incorrect" at the bottom of drafts (pattern G2-D, "Provide low performance alerts") — [Microsoft HAX Toolkit](https://www.microsoft.com/en-us/haxtoolkit/?p=8085)
- Microsoft Copilot FAQ: for an incorrect response, "provide that feedback by clicking thumbs down and providing additional comments in the feedback form" — [Microsoft Support](https://support.microsoft.com/topic/cbe05878-d68d-4d9d-83c1-5b47d6b76792)
- Looker: Gemini products "can generate output that seems plausible but is factually incorrect"; users should "validate all output from Gemini for Google Cloud products before you use it"; each response can be rated "Good response" or "Bad response" — [Google Cloud overview](https://docs.cloud.google.com/looker/docs/conversational-analytics-overview); feedback icons rate "the quality and accuracy" of each Gemini in Looker task — [Looker troubleshooting Gemini](https://docs.cloud.google.com/looker/docs/troubleshooting-gemini)
- Google's consumer Gemini help: "Gemini can hallucinate and present inaccurate information as factual. If you see a hallucination ... click the thumbs down button" — [Google Gemini help](https://support.google.com/gemini/answer/16279220)
- Tableau Pulse: "Thumbs-up and thumbs-down feedback personalizes future insights," controlled by a "Personalized Insight Ranking" site setting that is on by default; AI in Tableau is "built on the Einstein Trust Layer"; analysts can turn insight types off — [Tableau Help](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm); Tableau AI features are off by default and must be enabled by an administrator — [Tableau AI features](https://help.tableau.com/current/tableau/en-us/tableau_gai_solutions.htm)
- Tableau "not helpful" reasons include "biased or harmful content, inaccurate values, or incomplete output"; feedback "can't be undone" (secondary, O'Reilly) — [O'Reilly: Tableau Pulse for End Users](https://www.oreilly.com/library/view/learning-ai-tools/9781098175771/ch04.html)
- Amazon Quick: stories are "a starting point to customize and expand" and fully editable by the author before sharing — [AWS docs](https://docs.aws.amazon.com/quick/latest/userguide/working-with-stories.html); AWS says users "are frequently skeptical about the accuracy of answers because a single visual answer lacks the context," which is why stories embed the visuals — [AWS BI blog](https://aws.amazon.com/blogs/business-intelligence/enhance-your-analytics-embedding-experience-with-generative-bi-capabilities)
- ThoughtSpot states its AI "should be accurate, transparent, and trustworthy" and that it is "committed to complying with the [EU AI] Act as an AI provider" — [ThoughtSpot trust](https://www.thoughtspot.com/trust/enterprise-grade-ai)
- Anthropic Citations return `cited_text` with document locations so apps can "surface sources to your users" — [Anthropic Citations docs](https://platform.claude.com/docs/en/build-with-claude/citations)
- Proof-Carrying Numbers proposes that the renderer, not the model, marks numbers as verified, and "all others default to unverified" — [arXiv 2509.06902](https://arxiv.org/abs/2509.06902)

### Inferences
- LDT can go further than any vendor at low cost because its facts are its own: render each number in the narrative as a span linked to the fact (and the indicator page), mark unmatched numbers visibly, and log feedback with a reason code against the fact ID and model version, which is exactly the data needed to tune the ranking later.
- A fixed label such as "Generated from LDT 2025 release data on [date]; numbers checked against the published scores" is stronger and more specific than "AI-generated content may be incorrect," and the OSR finding that generic caution phrases get ignored argues for the specific form.

### Gaps
- No vendor publishes feedback volumes, accuracy rates or how thumbs-down data is used beyond "personalisation."
- The exact in-product disclaimer strings for Power BI and Looker were not found on an official page; the HAX example is Outlook.
- An aggregator claims Microsoft will drop the default "may be inaccurate" warning in favour of an admin "AI Disclaimer with Heightened Awareness" option; unverified against a Microsoft source — [reads.alibaba.com](https://reads.alibaba.com/microsoft-copilot-will-remove-the-ai-content-may-be-inaccurate-warning-by-default/)

## Cost and latency at about 1,100 units per yearly release, and caching or batch patterns

### Takeaway
At LDT scale generation is cheap enough to be a non-issue (single-digit dollars per release even on a frontier model, under one dollar on a mini model), and the product pattern is offline generation at release time with results stored and served as static content; the OpenAI Batch API halves cost and fits a whole release in one batch, so latency only matters if LDT regenerates on demand.

### Cited Findings
- OpenAI Batch API: "50% cost discount compared to synchronous APIs"; "completes within 24 hours (and often more quickly)"; up to 50,000 requests and a 200 MB input file per batch; supports `/v1/responses` and `/v1/chat/completions`; "Batch API rate limits are separate from existing per-model rate limits" — [OpenAI Batch guide](https://developers.openai.com/api/docs/guides/batch)
- Structured Outputs are supported in "the Batch API" as well as Responses and Chat Completions — [OpenAI Structured outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs)
- OpenAI list prices per 1M tokens (input / cached input / output), as of the pricing page read on 2026-10-29: gpt-5.4 $2.50 / $0.25 / $15.00; gpt-5.4-mini $0.75 / $0.075 / $4.50; gpt-5.4-nano $0.20 / $0.02 / $1.25; gpt-5-mini $0.25 / $0.025 / $2.00; gpt-5-nano $0.05 / $0.005 / $0.40; gpt-5.6-sol $4.00 / $0.40 / $20.00 (promotional through at least 2026-11-21); batch is 50% of standard and cached input is 90% cheaper — [OpenAI pricing](https://developers.openai.com/api/docs/pricing)
- OpenAI structured outputs: "The first request with a new schema has added latency; later requests with the same schema do not" — [OpenAI Structured outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs)
- Anthropic Citations: `cited_text` "does not count toward your output tokens" and is not counted as input when passed back — [Anthropic Citations docs](https://platform.claude.com/docs/en/build-with-claude/citations)
- Power BI's product pattern for persistence: the prompt is stored "with report metadata ... so it can generate the summary each time a report loads," and viewers must press refresh after filtering — [Microsoft Learn](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-create-narrative); a March 2026 feature summary added an auto-refresh option for the AI Narrative visual (community reply, secondary) — [Fabric community](https://community.fabric.microsoft.com/t5/Service/Copilot-Narrative-Bookmarks/m-p/5332452)
- Tableau Pulse generates insights per metric and per viewer context ("the filtered context the viewer is using") and delivers digests by email and Slack, i.e. generation is scheduled, not interactive — [Tableau Help](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm); [InterWorks](https://interworks.com/blog/2024/02/28/take-your-pulse-how-does-tableau-pulse-work/)
- Looker caps conversational queries at 50,000 rows and answers one visualisation per question, so its summaries are per-question and on demand — [Google Cloud overview](https://docs.cloud.google.com/looker/docs/conversational-analytics-overview)

### Inferences
- Worked estimate (assumptions: 1,500 input tokens of fact sheet plus system prompt and 400 output tokens per municipality; 1,100 municipalities; one generation pass plus one verification pass of equal size): gpt-5-mini synchronous about $2.60 per release, batch about $1.30; gpt-5.4 synchronous about $21, batch about $11. Prompt caching on the shared system prompt lowers the input side further. These are arithmetic from the list prices above, not measured.
- A full release (1,100 requests) fits in a single batch file far below the 50,000-request limit; the 24-hour window is acceptable for a yearly release pipeline, and separate batch rate limits mean it cannot starve interactive use.
- Pattern to copy: generate at release time, store narrative plus fact sheet plus `fact_ids` per sentence plus model and prompt version in Supabase, serve statically from Next.js, and regenerate only when the release data or prompt version changes (content-hash the fact sheet as the cache key). This is Power BI's "stored prompt, refresh on demand" turned into "stored output, refresh on data change."
- Provider-neutral note: batch and prompt-cache discounts are OpenAI features; Anthropic offers its own batch and caching, and the stored-output pattern makes the pipeline indifferent to provider.

### Gaps
- No vendor or paper publishes per-narrative generation latency; typical numbers (seconds for a few hundred output tokens) are common knowledge but I found no citable primary source for them in this pass.
- No public benchmark of narrative generation cost at the thousand-entity scale was found; the estimate above is derived.
- The OpenAI pricing page lists model names (gpt-5.6-sol, gpt-5.4) that should be re-checked against the models LDT actually calls before budgeting.
